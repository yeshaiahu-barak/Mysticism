# מסמך אפיון טכני וארכיטקטורה - מערכת המיסטיקה

## 1. ארכיטקטורה כללית
מערכת מבוססת "Serverless" (תשתיות Supabase) המכילה שני מודולי צד-לקוח (Client-Side).
הלוגיקה העסקית (נומרולוגיה/אסטרונומיה) מתבצעת בדפדפן הלקוח כדי להפחית עומס שרת (Edge Compute).

## 2. פירוט מודולים

### מודול 1: צד משתמש קצה (`index.html`)
* **אבטחה וסניטציה:** שימוש בפונקציות `escapeHTML` ו-`sanitizeDigits` למניעת חדירות XSS ובדיקת תקינות.
* **מודולריות פנימית:** 
  * **Config:** אכלוס מילוני בסיס (Fallback).
  * **Calculators:** פונקציות טהורות ללא תלות לחישוב גימטריה וצמצום מספרים.
  * **API Managers:** ניהול בקשות אסינכרוניות מול Nominatim (Debounced) ו-Hebcal.
* **ניהול מצב אופליין:** אירועי `window.online/offline` המסנכרנים נתונים ל-`localStorage` ומשדרים לשרת בחזרת הרשת.

### מודול 2: פאנל ניהול אדמיניסטרטיבי (`admin.html`)
* **בקרת גישה (Access Control):** אימות מבוסס OAuth דרך שרתי Google. בדיקת הרשאה קשיחה (Hardcoded ACL) המאפשרת גישה אך ורק לכתובת `4990920@gmail.com`.
* **תצוגת נתונים מופרדת (Decoupled View):** טעינת כל עמודות המסד לזיכרון המקומי (לייצוא CSV מלא), אך בניית טבלה DOM דינמית המציגה רק 6 עמודות קריטיות (מניעת עומס קוגניטיבי).

## 3. סכמת מסד נתונים (Supabase PostgreSQL)

### טבלה: `reports_log` (רישום פעילות)
| שם עמודה | סוג נתונים | תיאור / ייעוד |
| :--- | :--- | :--- |
| `id` | int8 (PK) | מזהה רשומה ייחודי |
| `created_at` | timestamptz | חותמת זמן של יצירת הרשומה בשרת |
| `action_date` | date | תאריך הזנת הטופס |
| `action_time` | time | שעת הזנת הטופס |
| `action_type` | text | סוג הפעולה (למשל basic_report) |
| `first_name` | text | שם פרטי |
| `last_name` | text | שם משפחה |
| `phone` | text | מספר נייד |
| `birth_date` | date | תאריך לידה |
| `city` | text | עיר הלידה |

### טבלה: `dynamic_texts` (מילון מונחים דינמי)
| שם עמודה | סוג נתונים | תיאור / ייעוד |
| :--- | :--- | :--- |
| `id` | int8 (PK) | מזהה |
| `category` | text | קטגוריה (`numerology`, `zodiac`, `ascendant`) |
| `item_key` | text | מפתח (למשל `1`, `5`, `טלה`) |
| `content` | text | התוכן שיוצג למשתמש על המסך |
